# Как работает оффлайн режим

RSVP Reader состоит из двух независимых локальных слоёв.

## 1. Cache API через service worker

`service-worker.js` кеширует app shell:

- `index.html`
- `style.css`
- `app.js`
- `epub-parser.js`
- `vendor/jszip.min.js`
- `manifest.json`
- `sample_text.txt`

После первой загрузки браузер может открыть приложение без сети. Навигация получает `index.html` из кеша, а статические файлы обслуживаются по стратегии stale-while-revalidate: сначала быстрый кеш, затем тихое обновление из сети, если сеть есть.

## 2. IndexedDB для данных пользователя

Книги больше не хранятся большим JSON в `localStorage`. Для этого используется IndexedDB база `rsvp-reader-db`:

- store `books`: текст книги, название, количество слов, последняя позиция, закладки;
- store `kv`: черновик, служебные флаги миграции и дополнительные настройки.

`localStorage` оставлен для совместимости со старыми версиями: старый `rsvp_text`, `rsvp_bookmark`, `rsvp_library` мигрируют при первом запуске, а настройки продолжают дублироваться туда.

## EPUB без интернета

EPUB это ZIP-архив с HTML/XHTML-файлами. DOCX тоже ZIP-архив с XML-документами. Для распаковки используется локальный файл `vendor/jszip.min.js`, который кешируется service worker. Поэтому после установки приложения можно загружать новые EPUB и DOCX даже без доступа к CDN.

TXT, FB2/XML, HTML, Markdown и RTF разбираются встроенными браузерными API без сетевых запросов. PDF/MOBI не включены намеренно: для них нужен отдельный тяжёлый движок, который увеличит оффлайн-пакет и усложнит поддержку.

## Практический сценарий

1. Первый раз открываете приложение с интернетом.
2. Service worker сохраняет файлы приложения.
3. Загружаете TXT/EPUB или вставляете текст.
4. Сохраняете книги и закладки в библиотеку.
5. После этого приложение, книги, прогресс и закладки доступны оффлайн в этом браузере.

Импорт/экспорт библиотеки создаёт JSON-файл, который можно перенести в другой браузер или сохранить как резервную копию.
