# HummingRead visual QA evidence

Capture environment: Chromium `151.0.7922.34`, local production server at `127.0.0.1:8081`, 2026-08-11. Regenerate with `npm run test:visual`; extension evidence is generated by `HUMMINGREAD_EXTENSION_ARTIFACT_DIR=artifacts/visual npm run test:extension`.

Generated evidence lives in the ignored local directory `artifacts/visual/` so review screenshots do not enter the public build or source history.

## Matrix inspected

- Fresh phone first viewport: 320×568, 375×667, 390×844, and 430×932. Both **45-second demo** and **Import your book** are fully visible; automated geometry also asserts this and horizontal overflow ≤1 px.
- Fresh 390×844 Russian and English full page: localized headline/buttons fit; Pico’s hero tail crosses the hero/flow boundary without covering copy.
- Returning reader 390×844: title/progress/time remain readable; Pico stays inside the reserved right side and crosses only the card’s right/bottom edges; arrow remains above the artwork.
- Phone landscape 568×320 and iPad landscape 1024×768 focus mode: word, pause context, explicit rewind, WPM, scrubber, and bottom play/pause target remain reachable.
- Focus mode 390×844 light/dark: paused context visibly anchors the focus word; normal controls are unobstructed. A separate guided-demo capture shows the step-2 coach and its rewind action.
- iPad 1024×1366 portrait, 1366×1024 landscape, and desktop 1440×1000: source dock, product story, legal links, and responsive columns do not clip or produce scroll traps.
- Chrome popup, standalone dark reader, and protected-page error: Pico crosses the reader-card boundary; the popup’s local actions are primary; WPM/rewind/progress/context remain legible; the protected error directs the user back without pretending Chrome permits extraction.
- Social preview 1200×630: button copy now fits after correcting the original overflow.

## Overlap and interaction checks

The chosen depth system is intentionally limited to four scenes: hero tail → flow map, Chrome flight pose → card right/bottom, returning-card pose → reserved right/bottom edge, and the product-story transition. Extension reader Pico also crosses the reader shell’s top boundary. Artwork uses `pointer-events: none`; text and controls sit in higher readable layers. The Chrome card received extra mobile bottom reserve so the bird no longer sits under installation copy.

## Accessibility and motion checks

- All tested action targets remain at least 44 CSS px; focus mode compact geometry is regression-tested.
- Keyboard/focus, dialog focus trap, names, EN/RU switching, and protected errors are covered by application/extension tests.
- `prefers-reduced-motion` disables hover/flight animation; capture code also supports a reduced-motion context.
- Ink/paper and paper/navy remain the primary text pairs; mint/amber/cobalt are accents and fills rather than low-contrast body text.
- 1024/512/32 app icons and 16/128 extension icons were dimension-checked and have no alpha. The App Store 1024 icon therefore meets the no-alpha requirement.

Final App Store and Chrome Web Store screenshots still require owner-approved brand/domain/support details and capture from the final submitted builds/account surfaces. These local images are review candidates, not a claim of store publication.
